# Live Text for Video

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語** | [한국어](README.ko.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Русский](README.ru.md)

**動画を一時停止して、画面右下のアイコンをクリックすると、画面内の文字がそのまま選択できるようになります。**

認識エンジンは Apple の **Vision フレームワーク** —— Safari の「ライブテキスト」と**まったく同じエンジン**なので、精度は同等です。

おまけ：認識結果は**本物の DOM テキスト**として配置されるため、Yomitan などの辞書拡張機能で**そのままホバー検索**できます。コピーする必要はありません。

---

## 何を解決するのか

Safari では動画を一時停止すると「ライブテキスト」ボタンが現れ、画面内の文字を直接選択・コピーできます。

しかし Chrome にはこの機能がありません —— **Web ページのサンドボックスからはシステムの OCR にアクセスできない**からです。フロントエンドだけで実現しようとすると汎用 OCR モデルをブラウザに同梱するしかなく、精度も速度も見劣りします。

このプロジェクトは **Chrome 拡張機能 + 小さなローカルヘルパー**で Safari の体験を Chrome に持ち込みます。拡張機能が UI とフレーム取得を担当し、ヘルパーが Apple の Vision エンジンを呼び出します。

---

## 動作環境

| 項目 | 要件 |
|---|---|
| OS | **macOS 13 以降**（それ以前は「言語の自動検出」機能がありません） |
| CPU | Apple Silicon / Intel どちらでも（バックエンドは Universal Binary） |
| ブラウザ | Chrome / Edge / Brave / Vivaldi / Opera（Chromium 系） |
| バックエンドをビルドする場合 | Command Line Tools：`xcode-select --install` |

> **Windows / Linux では動作しません** —— エンジンが macOS 専用のためです。
> **Safari も非対応** —— 拡張機能の API が Chrome 系と互換性がありません。
> 同じ Mac の**別の macOS ユーザー**は、それぞれ一度インストーラを実行する必要があります（登録はユーザー単位）。

## インストール

### ステップ 1：クローンと登録

```bash
git clone https://github.com/ChenZhuo4649/live-text-for-video.git
cd live-text-for-video
./install.sh
```

スクリプトの動作：

1. OS のバージョンと CPU アーキテクチャを確認
2. OCR バックエンドを準備 —— 使えるものが既にあればスキップ、なければ `swiftc` で **Universal Binary** をビルド
3. この Mac 上の**すべての Chromium 系ブラウザ**にバックエンドを登録
4. 拡張機能のインストール手順を表示

### ステップ 2：拡張機能をインストール

1. `chrome://extensions` を開く
2. 右上の **「デベロッパー モード」** をオン
3. **「パッケージ化されていない拡張機能を読み込む」** をクリックし、リポジトリ内の `extension/` フォルダを選択

拡張機能 ID は次のように表示されるはずです：

```
hmigekegioajglfmifdfofilgigpbcah
```

> **この ID は拡張機能に埋め込まれた公開鍵から算出され、インストールパスに依存しません。**
> 別の PC、別のフォルダ、別のブラウザでも同じです —— だからインストーラは ID のコピーを求めません。

表示が異なる場合は、拡張機能を**削除してから読み込み直してください**。

## 使い方

1. 任意の動画ページを開く（YouTube / ニコニコ / どこでも）
2. **一時停止**
3. 動画の**右下に小さな丸いアイコン**が現れる
4. **それをクリック**
5. 約 0.5〜1 秒待つと、画面内の文字が選択可能になり、**薄い青い下地が一瞬光って**文字の位置を教えてくれます
6. **ドラッグして選択 → `Cmd+C`**
7. **もう一度アイコンをクリック**すると解除され、画面が元に戻ります

文字ブロックにマウスを乗せると再びハイライトされるので、位置を見失いません。

## 認識精度（実測値）

| 内容の種類 | 結果 |
|---|---|
| URL、コード、大きめの高コントラスト文字 | ✅ 完全一致 |
| 中国語 / 日本語の字幕 | ✅ 完全一致 |
| 密集したターミナル文字 | ✅ 128 行中 72% が完全一致 |
| 低コントラストの灰色文字 | ❌ 失敗するが、信頼度が 0.3 まで下がるので結果の信頼性を判断できる |

処理時間：一般的な画面で **0.5〜1 秒**、密集したターミナル画面で約 **1.1 秒**。

## 言語設定

**既定では言語を自動判定**します（Vision の `automaticallyDetectsLanguage` を使用）。中国語・英語・日本語をそのまま扱えます。

> **`ja-JP` と `zh-Hans` を同時に渡してはいけない理由**：Vision の言語パックは**排他的**です。
> 両方を渡すと、中国語が繁体字や日本語の漢字異体字に化けます
> （师→姉、试→試、给→給、这→汶）。しかも処理時間がほぼ 2 倍になります。
> 同じ日本語の試験画面での実測：`zh-Hans` のみで **11 行**、`auto` で **44 行**。

画面が単一言語だと分かっている場合は、手動指定のほうが**速く**なります：拡張機能のアイコンをクリック →「中文 + 英文」または「日文 + 英文」を選択。即座に反映されます。

## 日本語辞書拡張機能との併用（Yomitan など）

テキストレイヤーは**意図的に通常の DOM に置いています**（Shadow DOM に隠していません）。これにより Yomitan などの辞書拡張機能がスキャンでき、**Shift を押しながらホバーするだけで語句を調べられます**。コピーしてから別の場所に貼る必要はありません。

そのために 3 つの調整を行っています：

| 調整 | 理由 |
|---|---|
| `color: #fff` + `-webkit-text-fill-color: transparent` | 辞書拡張機能は `color` で「表示されている本文かどうか」を判定する場合があり、`transparent` を直接指定するとスキップされる可能性があります。この書き方なら color は白のまま、塗りだけが透明 —— 見た目は同じ（不可視）で、判定には有利です |
| **2 段階の幅補正**（フォントサイズ自動調整 + letter-spacing） | 辞書は「マウス座標 → 文字インデックス」で検索します。描画幅が画面実際の幅と一致しないと、文字インデックスが**累積的にずれます** —— 症状は「行頭の語は正確だが、行末に近づくほどずれる」 |
| CJK テキストの**半角スペースを全角に変換** | OCR は半角スペース（全角の約 1/4 幅）を返すことが多く、その後ろの文字が全体的に前へずれます |

**2 段階補正の方法**：

```js
// ステップ 1：実描画幅から適切なフォントサイズを逆算
//（letter-spacing だけを調整すると、フォントが大きい場合に文字が重なって窮屈になり、位置判定も鈍くなる）
newSize = curSize * (目標幅 / 自然幅)      // 0.6〜1.7 倍に制限し、OCR 誤差で暴走しないようにする

// ステップ 2：残りの誤差を letter-spacing で詰める
letterSpacing = (目標幅 - 自然幅) / (文字数 - 1)
```

補正後の実測では**幅の誤差は 0、letter-spacing もほぼ 0** になります。

> ⚠️ **この補正に `transform: scaleX` を使わないでください** —— マウスのヒットテストを妨げ、ドラッグ選択とホバー位置が両方壊れます。

## 仕組み

```
動画が一時停止
   └→ content.js が動画の右下にアイコンを描画（独自 DOM、プレイヤーには触れない）
        └→ クリックすると
             ├→ sw.js が chrome.tabs.captureVisibleTab を呼ぶ
             │       （合成済みピクセルを取得するため、クロスオリジンの canvas 汚染を回避できる）
             ├→ content.js が canvas で動画領域を切り出す（レターボックスを除去）
             ├→ Native Messaging パイプでローカルバックエンドへ送信（ネットワーク不使用）
             ├→ バックエンドが Vision で認識し、テキスト + 正規化座標 + 信頼度を返す
             └→ content.js が元の位置に「透明だが選択可能な」テキストレイヤーを重ねる
```

知っておくと良い 2 点：

- **座標の反転**：Vision の正規化座標は原点が**左下**、CSS は左上なので、描画時に上下を反転します。
- **撮影のタイミング**：スクリーンショットの前にアイコン自身を隠します。そうしないとアイコンが画面に写り込み、OCR に拾われてしまいます。

## 既知の制限

| 制限 | 説明 |
|---|---|
| プレイヤーの UI も認識される | **合成された画面ピクセル**を取得するため、プログレスバーやボタンの文字も写り込みます。Safari にはこの問題がありません（動画フレームそのものを使うため） |
| DRM コンテンツは不可 | Netflix などは黒いフレームになります |
| まれに 1 文字分ずれる | 漢字 / かな / 数字 / 記号は本質的に幅が異なり、完全な整列は不可能です |
| デベロッパーモードの通知 | Chrome の起動時に「デベロッパー モードの拡張機能を無効にする」という通知が出ます。定例の案内で、動作には影響しません |

## トラブルシューティング

ログは**ページ自身のコンソール**に出ます（拡張機能ページではありません）：動画ページで `F12` → Console → `[Live Text]` を探してください。

| 症状 | 原因 | 対処 |
|---|---|---|
| アイコンが現れない | ページが未読込、または `<video>` を使っていないサイト | ページを再読み込み |
| `本机 OCR 后端未连接：...forbidden` | 登録ファイルに拡張機能 ID がない | `./install.sh` を再実行。改善しなければブラウザを再起動 |
| `Error when communicating with the native messaging host` | バックエンドの起動に失敗 | `./host/livetext-ocr --help` を手動実行して動くか確認 |
| `画面里没有识别到文字` | そのフレームに文字がない、または小さすぎる | 文字のあるフレームで試す |
| 文字化けする | 言語判定を誤った | 拡張機能のアイコンから言語を手動指定 |

## アンインストール

1. `chrome://extensions` → **Live Text for Video** → **削除**
2. 登録ファイルを削除（ブラウザ名は Chromium / BraveSoftware/Brave-Browser / Microsoft Edge / Vivaldi などに読み替え）：

```bash
rm "$HOME/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.livetext.videoocr.json"
```

3. リポジトリのフォルダを削除

**他の拡張機能への影響はゼロ**、残留物もありません。

## プライバシー

**画像が Mac の外に出ることはありません。** 経路はすべてローカルです：

```
拡張機能がフレームを取得 → ローカル stdio パイプ → オンデバイス Vision OCR → テキストを返す
```

ネットワークリクエストも、クラウド API も、テレメトリもありません。

## 開発

### 構成

```
live-text-for-video/
├── install.sh                    一括セットアップ：バックエンド準備 + 登録
├── host/
│   ├── livetext-ocr.swift        バックエンド本体（OCR / draw / langs / stdio の 4 モード）
│   ├── build.sh                  Universal Binary（arm64 + x86_64）をビルド
│   └── livetext-ocr              ビルド成果物（.gitignore で除外）
├── extension/
│   ├── manifest.json             `key`（公開鍵）を含み拡張機能 ID を固定
│   ├── content.js                ページに注入されるメインロジック
│   ├── content.css               アイコンとテキストレイヤーのスタイル
│   ├── sw.js                     service worker（スクリーンショット + 転送）
│   ├── popup.html / popup.js     言語切り替えパネル
│   └── icons/
├── poc/                          プロトコル自己テストツールとテスト画像
└── PoC-结果报告.md                精度の実測データ全文
```

### 変更を反映させる方法

| 変更箇所 | 反映方法 |
|---|---|
| `extension/` 以下の js / css / html | `chrome://extensions` で該当拡張機能の**再読み込み**をクリックし、動画ページを再読み込み |
| `host/` 以下の Swift ソース | `./build.sh` を再実行。**ブラウザの再起動は不要**（呼び出しのたびにプロセスが起動されるため） |
| 登録マニフェスト自体 | `./install.sh` を再実行。それでも反映されなければブラウザを再起動（マニフェストはキャッシュされます） |

### バックエンドを単体で使う（ブラウザなし）

```bash
cd host
./livetext-ocr ../poc/real_easy.jpg                    # 認識して JSON を出力
./livetext-ocr ../poc/real_easy.jpg --min-conf=0.5     # 低信頼度の行を除外
./livetext-ocr ../poc/real_easy.jpg --langs=auto       # 言語を自動判定（既定）
./livetext-ocr langs                                   # この Mac で利用可能な言語一覧
./livetext-ocr draw img.png result.json -o boxes.png   # 認識枠を画像に描いて座標を目視確認
```

### 通信プロトコルの単体テスト

ブラウザなしで「4 バイトの長さプレフィックス + JSON」というプロトコルを検証できます：

```bash
python3 poc/test_stdio.py host/livetext-ocr poc/real_easy.jpg
```
